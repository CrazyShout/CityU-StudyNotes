\StudyHeading{1}{1. Bit, byte and rate｜数据量、发送速率与传播速度}
\StudyTarget{Foundations-NetworkBasics__units}
\StudyTarget{Foundations-NetworkBasics__1-bit-byte-and-rate}


bit（比特）是一个二进制位，可取0或1。byte（字节）通常是8 bit，本课程采用8位字节。大写B与小写b不能省略：1500 B=12000 bit；文件大小是数量，2 Mbps是每秒2000000 bit的速率。


本课程网络速率用十进制：k=10\textsuperscript{3}，M=10\textsuperscript{6}，G=10\textsuperscript{9}。时间中milli是千分之一（ms=10\textsuperscript{-}\textsuperscript{3}s），micro是百万分之一（\ensuremath{\mu}s=10\textsuperscript{-}\textsuperscript{6}s）；Mbps中的大写M和ms中的小写m方向相反。KiB、MiB才明确表示1024、1024\textsuperscript{2}字节；题目中的Mbps按十进制换算。
\[
\text{发送时间}=\frac{\text{数据量(bit)}}{\text{速率(bit/s)}}.\tag{N.1}
\]


\begin{StudyBlock}{完整示范 / Worked example}{先统一bit与秒}
1500 B、R=2 Mbps。先换 \(L=1500\times8=12000\) bit，再算 \(L/R=12000/(2\times10^6)=0.006\) s=6 ms。用单位检验结果：“bit\ensuremath{\div}(bit/s)”得到s，表示所求的是时间。
\end{StudyBlock}


传播是另一件事。距离d=1000 km=10\textsuperscript{6}m，速度s=2\ensuremath{\times}10\textsuperscript{8}m/s，\(d/s=0.005\)s=5ms。提高链路发送速率R不等于让电磁信号速度s跟着翻倍。


\StudyImage{learning/foundation-notes/assets/network-units.png}
\StudyCaption{横轴是时间（ms）；上条为发送时延，下条为传播时延。}


本章的link bandwidth通常指bit/s容量；物理通信中的带宽也可能指Hz频宽，需要结合单位区分。


\textbf{变式 / Transfer:} 1000 B以10 Mbps发送，链路2000 km、传播速度2\ensuremath{\times}10\textsuperscript{8}m/s，忽略其他时延，整包到达要多久？ / Send 1000 B at 10 Mbps over 2000 km at propagation speed 2\ensuremath{\times}10\textsuperscript{8} m/s. Ignore other delays and find complete-packet arrival time.



\begin{StudySolution}{答案 / Answer}


发送0.8ms，传播10ms，总10.8ms。 / Transmission is 0.8 ms, propagation is 10 ms, total 10.8 ms. 计算前先把B换成bit、Mbps换成bit/s。


\end{StudySolution}


\textbf{English:} A byte contains eight bits. Convert all quantities before dividing; link rate and propagation speed describe different processes.

\end{StudySolution}

\StudyHeading{1}{3. Messages and bytes｜字段、分隔符与消息边界}
\StudyTarget{Foundations-NetworkBasics__messages}
\StudyTarget{Foundations-NetworkBasics__3-messages-and-bytes}


先看教学HTTP例子，保留英文协议文本：



\begin{StudyCode}
GET /notes.html HTTP/1.1\r\n
Host: example.com\r\n
Connection: close\r\n
\r\n
\end{StudyCode}


第一行是方法、路径、版本；后面是键值头字段。这里展示的\StudyInline{\textbackslash{}r\textbackslash{}n}是两个控制字节的可读写法：CR（carriage return，0x0D）和LF（line feed，0x0A），不是反斜杠、r、反斜杠、n四个普通字节。连续CRLF形成空行，结束头部；不是每个报文都有非空body。


文本字符串与字节序列要区分：Python的\StudyInline{'A'}是文本，\StudyInline{b'A'}是ASCII字节；\StudyInline{'A'.\allowbreak{}encode(\allowbreak{}'utf-8')\allowbreak{}}得到一个字节，而汉字在UTF-8下通常需要多个字节。因此\StudyInline{len(\allowbreak{}text)\allowbreak{}}不总等于网络发送的字节数。原Tutorial3使用ASCII报文，ASCII范围一个字符对应一个字节。


TCP提供有序字节流，应用必须自己定义消息边界；一次\StudyInline{send}不保证对应对方一次\StudyInline{recv}。UDP保留数据报边界，但接收缓冲不够会截断；可靠性与顺序不是默认保证。这里先知道“读到了几个字节”和“收齐一个完整应用消息”可能不同。


\textbf{变式 / Transfer:} \StudyInline{b'OK\textbackslash{}r\textbackslash{}n'}有多少字节？报文头中的User-Agent能否证明实际浏览器品牌？ / How many bytes are in b'OK\textbackslash{}r\textbackslash{}n', and does User-Agent prove the actual browser identity?



\begin{StudySolution}{答案 / Answer}


4字节：O、K、CR、LF。User-Agent只是客户端提供的字段，可以修改；只能说明报文自称是什么。 / Four bytes; User-Agent is a client-supplied claim, not proof of the actual browser.


\end{StudySolution}


\textbf{English:} Preserve protocol delimiters exactly. Application messages need framing, especially over a TCP byte stream.

\textbf{补充提示（植树边界与 bit-time）：}（1）TCP 按字节编号时采用“左闭右开”或“首尾含端点计数”：起始序号 \(\mathrm{Seq} = s\)、携带 \(L\) 字节数据的报文段覆盖第 \(s, s+1, \dots, s+L-1\) 号字节，因此下一段紧接着的起始序号与对方的累积确认号都是 \(s + L\)（如 \(\mathrm{Seq}=127\)、长 \(80\text{ B}\) 覆盖 \(127..206\)，下一个期待序号是 \(127 + 80 = 207\)，切忌减 1 误写成 \(206\)）。（2）链路层常把“发送 1 个比特所需的时间 \(1/R\)”记作 \textbf{1 bit-time}：例如在 \(R = 10\text{ Mbps}\) 以太网上，\(1\text{ bit-time} = 0.1\;\mu\text{s}\)，\(576\text{ bit-times} = 57.6\;\mu\text{s}\)；用 bit-time 直接加减传播与发送长度，就无需中途反复换算微秒。






\StudyHeading{1}{5. CIDR prefixes and longest prefix match｜把 32 位地址切成对齐的地址块}
\StudyTarget{Foundations-NetworkBasics__cidr-lpm}
\StudyTarget{Foundations-NetworkBasics__5-cidr-prefixes-and-longest-prefix-match}


在 §2 里我们知道 IPv4 地址由 4 个 8 位字节（共 32 bit）组成。无类域间路由（CIDR）写作 \texttt{a.b.c.d/x}，意思是\textbf{最左边连续 \(x\) 个比特固定为子网前缀（network prefix），最右边剩余 \(h = 32 - x\) 个主机位（host bits）可在该子网内部自由取 \(0\) 或 \(1\)}。


做子网计算与路由查表时，只需按以下四步操作：
\begin{enumerate}[start=1]
\item \textbf{算块大小与可用接口数}：剩余 \(h = 32 - x\) 个主机位共有 \(2^h\) 个连续地址；扣掉主机位全 \(0\)（网络地址）和主机位全 \(1\)（本子网广播地址）后，最多可分配给主机与路由器接口的地址数是 \(2^{32-x} - 2\)。反过来，若题目要求某子网容纳至少 \(M\) 个接口，就找满足 \(2^h - 2 \ge M\) 的最小整数 \(h\)，对应前缀长度 \(x = 32 - h\)（例如要支持 106 个接口：\(2^6 - 2 = 62 < 106 \le 126 = 2^7 - 2\)，故需 \(h = 7\)，取 \texttt{/25}，块大小为 \(128\)）。
\item \textbf{切分非 8 倍数前缀（跨位边界按位与）}：当 \(x\) 不是 8、16、24 时，切分点落在某个字节内部。例如求 \texttt{137.189.178.73/17} 所在子网：前 16 位固定前两个字节 \texttt{137.189}，第 17 位是第 3 个字节的最高位（权重 \(128\)）。把 \(178 = 128 + 32 + 16 + 2\) 写成 \texttt{10110010}，保留最高位 \texttt{1}、把后面 15 个主机位全清零得网络地址 \texttt{137.189.128.0/17}；把后面 15 位全置 1（第 3 字节为 \texttt{11111111} \(= 255\)，第 4 字节为 \(255\)）得广播地址 \texttt{137.189.255.255}。
\item \textbf{块起始地址必须整除块大小（\(2^k\) 对齐铁律）}：在最后 1 个字节内切分 \texttt{/24}（共 256 个地址：\(0..255\)）时，块大小为 \(B = 2^{32-x}\) 的子网，其第 4 字节起始值\textbf{只能是 \(B\) 的整数倍}！例如 \texttt{/26}（\(B = 64\)）只能从 \texttt{.0, .64, .128, .192} 开始；\texttt{/25}（\(B = 128\)）只能从 \texttt{.0} 或 \texttt{.128} 开始。若 \texttt{.0/26}（占 \(0..63\)）已分给子网 1，那么子网 2 的 \texttt{/25} \textbf{绝不能}从 \texttt{.64} 起算（因为二进制前 25 位无法表示 \(64..191\) 这种跨半界区间），必须对齐到 \texttt{.128/25}（占 \(128..255\)），再把中间留出的 \(64..127\) 切出 \texttt{.64/28}（占 \(64..79\)）给更小的子网。
\item \textbf{最长前缀匹配（Longest Prefix Match, LPM）}：路由器转发表中可能有多条前缀同时匹配同一个目的 IP（包括兜底默认路由 \texttt{0.0.0.0/0}，即全星号通配 \texttt{*}）。逐位核对目的 IP 二进制串与各表项前缀，剔除但凡有 1 位不一致的表项；在所有完全匹配的表项中，\textbf{选择固定前缀位数 \(x\) 最长（最具体）的那一条}转发。
\end{enumerate}


\textbf{变式 / Transfer:} 在 \texttt{192.168.10.0/24} 内，子网 A 已占用 \texttt{192.168.10.0/27}（\(0..31\)）。现需给子网 B 分配支持 50 台主机的最小地址块，其起始子网地址与广播地址是什么？ / Inside \texttt{192.168.10.0/24}, \texttt{.0/27} is already taken. Allocate the smallest valid CIDR block for 50 hosts and state its network and broadcast addresses.



\begin{StudySolution}{答案 / Answer}


50 台主机需 \(2^h - 2 \ge 50 \implies h = 6\)（\(62 \ge 50\)），前缀为 \texttt{/26}，块大小 \(B = 64\)。因 \(0..31\) 已被占用，下一个能被 \(64\) 整除的合法起点是 \(64\)，故分配 \texttt{192.168.10.64/26}，广播地址为 \texttt{192.168.10.127}（中间 \(32..63\) 留给后续更小子网）。 / Need \(h=6\) (\texttt{/26}, block size \(64\)); since \(0..31\) is occupied, align to the next multiple of \(64\): \texttt{192.168.10.64/26} with broadcast \texttt{192.168.10.127}.


\end{StudySolution}

\StudyHeading{1}{6. Modulo-2 XOR arithmetic and polynomials｜CRC 为什么从不借位}
\StudyTarget{Foundations-NetworkBasics__xor-crc}
\StudyTarget{Foundations-NetworkBasics__6-modulo-2-xor-arithmetic-and-polynomials}


本课程出现两种完全不同的二进制校验运算，考场上千万不要混用：
\begin{itemize}
\item \textbf{传输层 UDP/TCP 检验和（Chapter 3 / Tutorial 5）}用的是\textbf{16 位反码算术（1's complement addition）}：列与列之间\textbf{正常向高位进位}，最高位溢出的进位还要回卷加到最低位，最后整体按位取反。
\item \textbf{链路层奇偶校验与循环冗余校验 CRC（Chapter 6 / Tutorial 11）}用的是\textbf{模 2 算术（\(\mathrm{GF}(2)\) 异或 XOR，记作 \(\oplus\)）}：每一位完全独立，\textbf{既不向高位进位，也绝不向高位借位}！因此模 2 加法与模 2 减法是同一个运算：相同得 \(0\)（\(0\oplus 0=0,\; 1\oplus 1=0\)），相异得 \(1\)（\(1\oplus 0=1,\; 0\oplus 1=1\)）。
\end{itemize}


做 CRC 编码或验算时，遵守三条死规则就不会出错：
\begin{enumerate}[start=1]
\item \textbf{生成多项式 \(G(x)\) 与二进制比特串互转（缺项必须补 0）}：最高次幂为 \(r\) 的生成多项式 \(G(x)\) 对应一个\textbf{长度为 \(r + 1\) 位}的二进制除数串，从 \(x^r\) 到常数项 \(x^0 = 1\) 逐次写出系数 \(1\) 或 \(0\)。例如 \(G(x) = x^4 + x^2 + 1 = 1\cdot x^4 + \mathbf{0}\cdot x^3 + 1\cdot x^2 + \mathbf{0}\cdot x^1 + 1\cdot x^0\)，对应的 5 位除数串是 \texttt{10101}（切勿漏掉缺项写成 \texttt{111}）；反过来 \texttt{1001} 对应 \(x^3 + 1\)（\(r = 3\)）。
\item \textbf{被除数末尾补 \(r\) 个 0，余数 \(R\) 严格保留 \(r\) 位（含前导 0）}：若除数 \(G\) 长 \(r + 1\) 位，先在原始数据比特串 \(D\) 末尾补上 \(r\) 个 \(0\)（相当于计算 \(D\cdot 2^r\)）。长除法每一步\textbf{只看当前余数窗口的最高位}：若最高位是 \(1\)，商写 \(1\) 并与 \(G\) 逐位异或；若最高位是 \(0\)，商写 \(0\) 并与全 \(0\) 异或，拉下下一位继续。最终剩下的余数 \(R\) \textbf{固定为 \(r\) 位}——若算出高位是 \(0\)（例如 \(r=4\) 时余数为 \texttt{0100}），前面的 \(0\) 也是必须拼接到帧尾的校验位，不能省写成 3 位 \texttt{100}。
\item \textbf{发送帧与接收端校验}：发送端传输拼接后的比特串 \(\langle D, R\rangle\)（因为在模 2 算术里加上 \(R\) 就等于减去余数 \(R\)，使得 \(D\cdot 2^r \oplus R\) 恰好被 \(G\) 整除）；接收端用同一个 \(G\) 去除收到的整帧，余数全 \(0\) 则判无错，非 \(0\) 则判有错。
\end{enumerate}


\textbf{变式 / Transfer:} 设生成多项式为 \(G(x) = x^3 + x + 1\)，数据为 \(D = \mathtt{1010}\)。写出二进制生成串 \(G\)、补零后的被除数，并求 3 位 CRC 余数 \(R\)。 / For \(G(x) = x^3 + x + 1\) and \(D = \mathtt{1010}\), write the binary generator \(G\), the zero-padded dividend, and the 3-bit CRC remainder \(R\).



\begin{StudySolution}{答案 / Answer}


\(G(x) = 1\cdot x^3 + 0\cdot x^2 + 1\cdot x^1 + 1\cdot x^0 \implies G = \mathtt{1011}\)（\(r = 3\)）。在 \(D\) 末尾补 3 个 0 得 \texttt{1010000}。模 2 长除：前四位 \(\mathtt{1010}\oplus\mathtt{1011}=\mathtt{0001}\)，依次拉下三个 0 得 \(\mathtt{1000}\oplus\mathtt{1011}=\mathtt{0011}\)，保留完整 \(r = 3\) 位得 \(R = \mathtt{011}\)，发送帧为 \texttt{1010011}。 / \(G = \mathtt{1011}\) (\(r=3\)), padded dividend \texttt{1010000}, and 3-bit remainder \(R = \mathtt{011}\) (transmitted frame \texttt{1010011}).


\end{StudySolution}


\textbf{English:} Keep 1's-complement checksums (with wraparound carry) distinct from modulo-2 CRC arithmetic (carry-free XOR); an \((r+1)\)-bit generator always appends an exact \(r\)-bit remainder including leading zeros.
